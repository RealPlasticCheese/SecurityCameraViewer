# Installing packaged web servers

Only the ASP.NET Core server and browser UI are packaged. No native desktop viewer,
source checkout or .NET SDK is needed on an installed host. The .NET runtime is
included; OS runtime libraries and FFmpeg remain prerequisites. MediaMTX is included.

## Packages

The Linux and Windows packages contain version and source-commit metadata in release.json. Each package has an adjacent SHA-256 checksum. Linux package checks use Ubuntu 24.04 and Fedora 43 containers. Windows package checks exercise installation, upgrade, service startup, and removal on a disposable host.

## Linux DEB / RPM

For Ubuntu 24.04 / Linux Mint 22, download the `.deb` and install with:

```bash
sudo apt install ./security-camera-viewer_1.0.BUILDID_amd64.deb
sudo security-camera-viewer-setup configure --start
```

For Fedora 43, download the `.rpm` and install with:

```bash
sudo dnf install ./security-camera-viewer-1.0.BUILDID-1.x86_64.rpm
sudo security-camera-viewer-setup configure --start
```

The RPM requires `/usr/bin/ffmpeg`. Enable the package source appropriate for your
distribution and codec needs first. `ffmpeg-free` is sufficient for package checks
on Fedora; other distributions may require RPM Fusion or another repository.
RPM format alone does not imply compatibility with every RHEL-family release.

Fresh installations create the `security-camera-viewer` system account and keep
the service stopped until explicitly started. Open `http://SERVER:5080/` and use
the existing browser controls to add cameras, enter credentials and set recording
directories. The service starts before login once enabled.

Installed paths:

| Path | Purpose |
| --- | --- |
| `/usr/lib/security-camera-viewer` | Package-managed application and dependencies |
| `/etc/security-camera-viewer/host.json` | Administrator-managed listener and paths |
| `/var/lib/security-camera-viewer` | Private writable settings, models and default recordings |
| `journalctl -u security-camera-viewer` | Service logs |

For an HTTP backend behind a local HTTPS proxy:

```bash
sudo security-camera-viewer-setup configure --bind 127.0.0.1 --port 5081 --start
```

Package upgrades retain host configuration, cameras, passwords, external recordings,
service enablement and certificates. Removal stops/removes the service but keeps
data and the account. Delete retained data explicitly only when no longer needed.
The package does not open firewall ports automatically.

The `.tar.gz` is a portable alternative for compatible Linux x64 systems. Extract
it, ensure FFmpeg is installed, and run `./SecurityCameraViewer.Web --settings
/absolute/private/path/settings.json`. Service installation for portable archives
is administrator-managed; native packages provide the complete managed service.

## Migrating an existing Linux service

The first DEB installation recognizes the unit generated by `web-service.sh`.
It backs up the existing settings to `settings.json.pre-package`, retains the
existing account and absolute settings/FFmpeg paths, and preserves its HTTP listener
(currently loopback 5081). Recordings are not moved. The old unit is retained as
`/etc/systemd/system/security-camera-viewer.service.pre-package`; a small drop-in
preserves the old account while the packaged systemd unit runs the new application.
Existing service overrides remain in place. Review custom overrides for references
to the old executable or checkout before deploying; unmanaged units are refused.

The checkout, Caddy configuration, Namecheap credentials, lego renewal timer and
certificates remain untouched. Existing HTTPS can continue on its original port.
The old checkout must remain available until the first migration is verified.

Use a versioned DEB and verify its SHA-256 checksum before installing. After upgrading, confirm the configured manifest endpoint responds and keep the previous package available for rollback. The repository’s Linux deployment helper verifies the checksum and health endpoint, and restores the previous package or legacy service if installation or verification fails.

## Windows wizard and silent setup

Run `SecurityCameraViewer-VERSION-win-x64-setup.exe` as an administrator. The wizard
offers installation location, HTTP port, service/manual mode, optional local-subnet
firewall access and FFmpeg installation through Windows Package Manager when missing.
If winget is unavailable, install FFmpeg separately, add it to PATH, then rerun setup.
Setup resolves Chocolatey launchers to the actual FFmpeg executable so service
shutdown and capture cancellation can stop the decoder process. For an ambiguous
installation, pass `-FfmpegPath C:\path\to\ffmpeg.exe` to `Setup-Server.ps1`.
The self-contained server and MediaMTX are installed without a .NET prerequisite.

Service mode uses Network Service and starts automatically. Administrator-owned
host settings live under `%ProgramData%\SecurityCameraViewer`; service-writable
camera settings, models and default recordings live in its `data` subdirectory,
separate from Program Files. Existing configuration is retained during upgrades. To change an installed
host's port, run `Setup-Server.ps1 -Reconfigure` with the desired options. Existing
user-mode installations need their settings copied explicitly while both copies
are stopped; setup does not guess which user's secrets should be imported.

```powershell
.\SecurityCameraViewer-VERSION-win-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /TASKS="service,ffmpeg" /PORT=5080 /LOG="setup.log"
```

`/HTTPSMODE=0|1|2|3` selects preserve, public ACME, DNS validation or local CA.
Use `/HOSTNAME=viewer.example.com` and `/DNSPROVIDER=cloudflare` when applicable.
These choices generate an HTTPS example for review; setup clearly separates this
from an activated and verified HTTPS site. The installer returns failure if host
configuration or service startup fails. Uninstall preserves private data and
certificates. Data deletion is a separate administrator operation.

The ZIP supports portable use. Extract and run `SecurityCameraViewer.Web.exe` with
FFmpeg on PATH, or run `Setup-Server.ps1` as administrator to configure a service.
`Start-Server.cmd` uses the installed ProgramData host configuration.

## HTTPS assistance

Existing proxies are always preserved. For new sites, both setup paths can generate
a Caddy site for public ACME, DNS validation or a local CA. Linux example:

```bash
security-camera-viewer-setup https --hostname viewer.example.com --mode dns \
  --provider cloudflare --backend-port 5081 --output viewer.caddy.example
```

On Windows the wizard generates `%ProgramData%\SecurityCameraViewer\viewer.caddy.example`.
Set the server backend to loopback, install Caddy, then review and import the site
into its configuration. Install the DNS provider module and configure its
provider-specific credential options/environment variables. Provider syntax differs;
the generated `dns PROVIDER` is a starting point, not a guarantee that all providers
work without additional fields. For Cloudflare, for example, use
`dns cloudflare {env.CLOUDFLARE_API_TOKEN}` with a scoped token in Caddy's service
environment. Do not place DNS tokens in Azure build artifacts or installer arguments.

DNS validation can issue publicly trusted certificates for a LAN-only hostname
without forwarding ports to the camera server. Own/control the domain and configure
DNS so clients resolve it to the server's LAN address. HTTP/TLS validation instead
requires public DNS and inbound reachability on the validation port (80 or 443).
Local CA mode requires trusting Caddy's root certificate on client devices.

Validate the combined configuration with `caddy validate --config Caddyfile`, reload
Caddy, then request `https://HOSTNAME/manifest.webmanifest` from a client with normal
certificate verification enabled. Caddy handles automatic issuance/renewal when
using its ACME provider; preserve its data directory across server upgrades.
Provision Caddy's service and firewall separately using its supported OS installation.

For the existing Linux Namecheap/lego setup, the package includes `web-https.sh`.
It retains the existing issuance, renewal and rollback support. Follow
[the Namecheap guide](https-namecheap.md); its `ports` command is for the older
checkout-managed service. For packaged services change the backend through
`security-camera-viewer-setup configure` and update the saved proxy settings together.
