Usually 554. Port 9000 is used by RXCamView's separate client service.

Use {channel:00} for 01, 02…; {channel} for 1, 2…; {channel0} for 0, 1…; {stream} for main (0) or substream (1).

Motion & recording

Record events, continuously, or whenever a motion-activated camera transmits video. Recordings include available audio.

Runs while the server is on, even with browsers closed or live viewing disconnected.

Recording storage

Create each folder on its mounted drive before adding it. Each drive keeps its own copy and storage limit.

The oldest unprotected recordings expire first. Protected recordings count toward each limit.

Changing folders leaves existing recordings in the old folder. Select that folder again to browse them.

Long activity is split into bounded clips. Pre/post-event buffering applies to Event mode. Continuous and available-video modes create consecutive segments without a RAM pre-event buffer. Pre-event coverage depends on bitrate and camera keyframes. The RAM limit excludes decoder and working buffers.

    Object rules

    Trigger objects start or extend automatic zone actions. Ignore objects can appear in live overlays but never trigger actions; a triggering person can still record beside an ignored animal. No action omits that class. These rules apply to AI and hybrid detection. Pixel-only motion cannot classify objects.

    A permissive gate lets AI check small movements. AI confirms objects in the same active zone. Checks continue for three seconds after motion stops.

    Higher resolution costs more processing. AI modes use at least 640 × 360 colour frames. The model also resizes its input; a higher source resolution cannot guarantee distant detections.

    Adaptive noise, lighting and diagnostics

    Learns bounded local variation during warmup and from background pixels. Can reduce vegetation flicker; test that small distant subjects still qualify.

    Averages nearby monitored pixels. Excluded timestamps do not bleed into detection. Smoothing can reduce very small subjects.

    Persistence requires a region to recur nearby; 1 disables this filter. Confirmation then requires consecutive frames above the moving-area threshold. Both add delay at lower analysis rates.

    Uses colour analysis and rejects moderate darkening with similar colour. Dark objects with similar colour can also be rejected; test on your footage. Colour processing adds load.

    Only filters overlay boxes. It does not change motion detection, recording or the hybrid gate.

    RTSP & ONVIF service

    Share individual cameras with Android viewers, recorders and other clients through this server.

    Server addresses

    Use this server's reachable LAN address. ONVIF runs on the existing web server; include its port. Keep the trailing /. RTSP uses its own port.

    Client login

    Client usernames/passwords support ASCII letters, digits and these symbols: ! $ ( ) * + . ; < = > [ ] ^ _ - { } @ # &. Spaces and other symbols are unsupported by the relay.

    Use this login in both RTSP and ONVIF clients. Camera passwords stay on the server. Changing the login restarts RTSP sessions. Protect the server data directory; client credentials must be stored privately for ONVIF and RTSP Digest support.

    ONVIF discovery

    Discovery uses IPv4 multicast on UDP 3702. If discovery is blocked, add a camera using its ONVIF address below. Android apps that accept only a host and port may require the recorder endpoint or a manual RTSP URL.

    Advanced relay settings

    Install MediaMTX beside the published server or provide its full path. See docs/streaming-service.md for the Windows and Linux setup commands.

    UDP requires an even RTP port and the next port for RTCP, such as 8000 and 8001.

    The control port listens on localhost and requires an internal credential. Feeds start on demand, keep their original codecs and include audio when available.

    Profile metadata overrides

    The service reads codec and resolution from camera metadata or FFprobe. Use an override when metadata is unavailable or incorrect, especially for motion-activated cameras, which are not polled. These values describe the stream; they do not change its encoding.

    Client connection addresses

    Save and enable the service, then copy an address into your client. Select ONVIF for discovery/profiles or RTSP for direct playback. H.265 profiles use Media2; clients without Media2 can use their RTSP addresses.
